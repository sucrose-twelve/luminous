# Database — Drizzle ORM 1.0 (rc) + Postgres

- Driver: `postgres` (postgres-js) via `drizzle-orm/postgres-js`. Client lives in
  `src/drizzle/index.ts` and is the only place a connection is created. Import
  `{ db, schema }` from `@/drizzle`.
- **Query with the SQL-like builder: `db.select()`, `db.insert()`, `db.update()`,
  `db.delete()`.** Don't use `db.query.*` (Relational Queries) for new code.
- Drizzle **1.0** declares relations with `defineRelations` (the v0 `relations()` helper
  is gone). Relations are still registered on the client but are documentation only,
  because reads go through `db.select()`.
- DB access is **server-only**: never import `@/drizzle` from a Client Component or a file
  that one imports.

## Files in `src/drizzle/`

| File                                 | Purpose                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------- |
| `index.ts`                           | `postgres()` client + `drizzle({ client, relations })`                    |
| `schema/<domain>.schema.ts`          | Tables for one domain (`accounts.schema.ts`, `contents.schema.ts`, …)     |
| `relations.ts`                       | `schema` object (all tables) + `defineRelations(schema, …)`               |
| `types.ts`                           | `X`, `XInsertValues`, `XUpdateValues` per table (`InferSelectModel` etc.) |
| `table-columns.ts`                   | `getColumns(table)` exports for building explicit selects                 |
| `utils.ts`                           | `sharedTimestampColumns`, `withPagination`                                |
| `seeds/index.ts` + `seeds/data/*.ts` | Idempotent seed script and its data                                       |
| `migrations/`                        | Generated by drizzle-kit — never edit by hand                             |

When you add a table: schema file → add to the `schema` object in `relations.ts` →
relations → types in `types.ts` → columns in `table-columns.ts` (if needed) → generate a
migration.

## Table conventions

Example from `schema/contents.schema.ts`:

```ts
export const seasons = pgTable.withRLS(
  "seasons",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    contentId: uuid("content_id")
      .notNull()
      .references(() => contents.id, { onDelete: "cascade" }),
    kind: varchar("kind", { length: 20 })
      .notNull()
      .default("season")
      .$type<Content.SeasonKind>(),
    seasonNo: integer("season_no"),
    title: varchar("title", { length: 255 }),
    status: varchar("status", { length: 20 })
      .notNull()
      .default("finished")
      .$type<Content.SeasonStatus>(),
    sources: jsonb("sources").notNull().$type<Content.SeasonSource[]>(),
    poster: text("poster_path").notNull(),
    releasedOn: date("released_on").notNull(),
    ...sharedTimestampColumns
  },
  (self) => [
    uniqueIndex("seasons_content_season_no_index")
      .on(self.contentId, self.seasonNo)
      .where(sql`${self.kind} = 'season'`),
    index("seasons_content_released_on_index").on(self.contentId, self.releasedOn)
  ]
)
```

- Primary keys: `uuid("id").defaultRandom().primaryKey()`.
- **Foreign keys must have the same type as the column they reference** (a `uuid` PK needs
  a `uuid` FK).
- TS property camelCase, SQL name snake_case, given explicitly:
  `isActive: boolean("is_active")`. The TS key may be shorter than the SQL name
  (`poster: text("poster_path")`, `thumbnail: text("thumbnail_path")`,
  `size: bigint("size_bytes")`). `pick` / `omit` and the code use the **TS key**.
- Timestamps are `timestamp(…, { withTimezone: true })`; spread `sharedTimestampColumns`
  into every table.
- Durations and playback positions are integer **seconds**.
- Every foreign key gets an index. A composite unique index whose **first** column is the
  FK counts (`seasons_content_released_on_index` covers `content_id`). Add indexes for
  every `where` / `orderBy` used on a hot path.
- Choose `onDelete` deliberately: `restrict` for accounts, `cascade` for owned children
  (episodes of a season).
- jsonb columns and string unions are typed with `.$type<…>()` using the global `Content`
  namespace in `src/types/schema.d.ts` (`Content.Kind`, `Content.Skip`,
  `Content.Fragment`, …). Add new types there.
- Tables use `pgTable.withRLS(...)`. Stay consistent for new tables.

### Media paths: full paths

- File columns store the **full absolute path** with forward slashes, e.g.
  `<CONTENTS_SOURCE_DIR>/Frieren/1/01.mp4`. The columns are `tracks.path`, `seasons.poster`
  (`poster_path`), `episodes.thumbnail` (`thumbnail_path`), `episodes.sprite`
  (`sprite_sheet_path`), and each `pathname` in `seasons.sources`. There's no media root
  in env, and the drive is simply part of the path.
- `seasons.sources` (jsonb `Content.SeasonSource[]`) lists **every audio version of the
  season**: `{ language, pathname, isDubbed }`, at most one with `isDubbed: false` (the
  original; a season may have only dubs) and each language once. `pathname` is the folder of `01.mp4`, `02.mp4`, … or,
  for a `movie`, the `.mp4` itself. Each track's `path` must be or sit under the
  `pathname` of the source in its language. Thumbnails and sprites sit in the season's art
  folder, `seasonArtDirectory(sourceDir, season)` in `@/libs/media`
  (`<contents.sourceDir>/Thumbnails/<name>`: `<season_no>` for a season, the file name for
  a movie, `<spinoff folder>/<season_no>` for a spinoff). `seasons.poster` may sit in any
  folder, so it is only checked for being absolute and an image. `tracks.path` is unique
  too.
- Write paths only from the import step, never from user input. Normalize before saving
  (`path.resolve(...).replaceAll("\\", "/")`).
- `sources`, `path`, `poster`, `thumbnail`, and `sprite` are **server-only**: omit them
  from anything returned to a Client Component. The browser addresses files by ID (see
  [video-streaming.md](video-streaming.md)).

## Data model

Existing tables (`schema/accounts.schema.ts`, `schema/contents.schema.ts`,
`schema/activities.schema.ts`):

| Table             | Key columns                                                                                                                                                                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accounts`        | id, role, username (unique), email (unique), password (scrypt hash), is_active, is_suspended                                                                                                                                                                               |
| `profiles`        | id, account_id (unique FK), display_name, avatar                                                                                                                                                                                                                           |
| `preferences`     | id, account_id (unique FK), audio_language, autoplay_next, auto_skip                                                                                                                                                                                                       |
| `contents`        | id, slug (unique), kind, title, `altTitles` → `alternative_titles` (jsonb), synopsis, source, genres (text[], GIN), `searchText` → `search_text` (generated, trigram GIN), **sourceDir** → `source_directory` (holds `Thumbnails/`)                                        |
| `seasons`         | id, content_id, kind (`Content.SeasonKind`, default `season`), season_no (nullable), title (trigram GIN), synopsis, status, **sources** (jsonb `Content.SeasonSource[]`), **poster** → `poster_path`, released_on (required, index)                                        |
| `episodes`        | id, season_id, episode_no, kind (`Content.EpisodeKind`, default `regular`), title, synopsis, **thumbnail** → `thumbnail_path`, **sprite** → `sprite_sheet_path`, `spriteGrid` → `sprite_sheet_grid` (jsonb `Content.SpriteGrid`), skips (jsonb `Content.Skip[]`), aired_on |
| `tracks`          | id, episode_id, language, is_dubbed, **path** (unique), mime_codec, size → `size_bytes`, duration → `duration_seconds`, width, height, init_end, fragments (jsonb)                                                                                                         |
| `watch_histories` | id, account_id, content_id (unique together), episode_id, position_seconds, duration_seconds, completed_at, watched_at                                                                                                                                                     |
| `watchlists`      | id, account_id, content_id (unique together), status (`Content.WatchStatus`), rating (1–5, nullable), is_favorite                                                                                                                                                          |

`key → column` marks a TS key that differs from its SQL column.

`episodes.kind` (`regular` | `special` | `ova` | `recap`, default `regular`) is for the
UI: label special episodes and group or filter them in the episode list. The card poster
comes from a season (`seasons.poster`).

A **season** is any part of a content: `seasons.kind` is `season` | `movie` | `special` |
`spinoff` (default `season`), so a franchise like Sword Art Online is one content with its
seasons, movies, and the Alternative spinoff. `season_no` is only the `N` of a "Season N"
label: required for `season`, `null` for `movie` (`seasons_season_no_check`), optional
otherwise (a spinoff may count its own seasons). It's unique per content only among
`season` rows (partial `seasons_content_season_no_index`). **Seasons are ordered by
`released_on`** (required), then `created_at` and `id`, never by `season_no`. A movie is a
season with one episode (`episode_no` 1).

A **track** is one playable `.mp4` file: one language/dub version of an episode, unique on
`(episode_id, language)`. The watch page addresses it as `?vid=<tracks.id>`. `mime_codec`,
`init_end`, and `fragments` are filled in by the import step (see
[video-streaming.md](video-streaming.md)).

Genres are a `text[]` on `contents` (filter with
`arrayContains(contents.genres, [genre])`, which the GIN index serves), not a join table.

`watch_histories` keeps **one row per account per content** (a movie or a whole series):
the latest episode and track watched and where playback stopped. It powers "Continue
watching"; there is no per-episode progress. Derive `content_id` from the episode on the
server when writing, never from client input. `watched_at` orders the row (`updated_at` is
null after the first insert). `watchlists` is the user's list: interest status, an
optional 1–5 rating, and a separate favorite flag.

The project has **no subtitles**: no table, route, `.vtt` files, or caption UI.

## Relations

Keep `relations.ts` in sync when adding tables. `schema` must contain every table, because
`drizzle-kit` and the client both read it.

```ts
import { defineRelations } from "drizzle-orm"

import * as accounts from "./schema/accounts.schema"
import * as contents from "./schema/contents.schema"

export const schema = Object.freeze({ ...accounts, ...contents })

export const relations = defineRelations(schema, (r) => ({
  contents: {
    seasons: r.many.seasons()
  },
  seasons: {
    content: r.one.contents({
      from: r.seasons.contentId,
      to: r.contents.id,
      optional: false
    }),
    episodes: r.many.episodes()
  }
}))
```

## Queries

Two conventions for every query:

- **Reference tables through `schema`**: `schema.contents`, `schema.seasons.contentId`.
  Don't destructure (`const { contents } = schema`).
- **Choose columns with es-toolkit `pick` / `omit`** over the column sets in
  `@/drizzle/table-columns` (`contentColumns`, `seasonColumns`, `episodeColumns`,
  `trackColumns`, `accountColumns`, …). Don't write column objects by hand.

```ts
import { eq } from "drizzle-orm"
import { omit, pick } from "es-toolkit"

import { db, schema } from "@/drizzle"
import { contentColumns } from "@/drizzle/table-columns"

export async function readContent(slug: string) {
  const [row] = await db
    .select(omit(contentColumns, ["searchText"]))
    .from(schema.contents)
    .where(eq(schema.contents.slug, slug))
    .limit(1)

  return row ?? null
}

export async function readContentCards() {
  return db
    .select(pick(contentColumns, ["id", "slug", "title", "kind"]))
    .from(schema.contents)
}
```

- Use `pick` when you need a few columns (cards, lists) and `omit` when you need almost
  all of them (detail pages). Either way, server-only columns (`sources`, `path`,
  `poster`, `thumbnail`, `sprite`, `password`) must not reach the client.
- For a single row, add `.limit(1)` and destructure `const [row] = …`, returning
  `row ?? null`.

For joins, nest one picked set per table. Keys like `id` would otherwise collide, and the
result rows come back nested:

```ts
import { asc, eq } from "drizzle-orm"
import { groupBy, pick } from "es-toolkit"

import { db, schema } from "@/drizzle"
import { episodeColumns, seasonColumns } from "@/drizzle/table-columns"

const rows = await db
  .select({
    season: pick(seasonColumns, ["id", "kind", "seasonNo", "title"]),
    episode: pick(episodeColumns, ["id", "episodeNo", "title"])
  })
  .from(schema.seasons)
  .innerJoin(schema.episodes, eq(schema.episodes.seasonId, schema.seasons.id))
  .where(eq(schema.seasons.contentId, contentId))
  .orderBy(
    asc(schema.seasons.releasedOn),
    asc(schema.seasons.createdAt),
    asc(schema.episodes.episodeNo)
  )

const episodesBySeason = groupBy(rows, (row) => row.season.id)
```

- **One query per list, never a query per item.** That means a join, or
  `inArray(column, ids)` followed by grouping in memory with `groupBy` from es-toolkit.
  Querying inside `.map()` is an N+1 bug.
- Use `leftJoin` when the joined row may be missing (a content with no seasons yet). The
  joined columns are then nullable in the result type.
- Operators come from `drizzle-orm`: `eq`, `and`, `or`, `inArray`, `arrayContains`,
  `ilike`, `isNull`, `desc`, `asc`, `count`, `sql`.
- When you add a table, export its column set from `table-columns.ts`
  (`getColumns(table)`).
- **Select only the columns you render.** `accounts.password` never leaves the auth module
  (`omit(accountColumns, ["password"])`).
- Run independent queries in parallel with `Promise.all`.
- Multi-step writes go in `db.transaction(async (tx) => { … })`.
- Upserts: `.onConflictDoUpdate({ target: [...], set: {...} })` (watch progress, watchlist
  toggles).
- Pagination: `withPagination(query.$dynamic(), page, take)` for small offsets; for long
  lists ("load more" rows, history) prefer keyset pagination
  (`where createdAt < cursor order by createdAt desc limit n`).
- Search: text search uses `pg_trgm` (the DB needs `CREATE EXTENSION pg_trgm` once). Match
  `contents.searchText` (title + alt titles) and `seasons.title` with `ilike` (substrings)
  or `query <% column` (typo-tolerant; the threshold is set on the connection in
  `drizzle/index.ts`); rank with `word_similarity()`. See `/browse`. Add the
  `Content.AlternativeTitles` key to `searchText` when that type gains one.
- Never build SQL with string concatenation; use the builder or the `sql` template tag (it
  parameterizes).
- Wrap catalogue reads in `"use cache"` + `cacheTag` (see [nextjs.md](nextjs.md)); don't
  cache per-user rows remotely.

## Migrations and seeds

`drizzle.config.ts` reads `./src/drizzle/schema/*.schema.ts` and writes to
`./src/drizzle/migrations`.

Use the `package.json` scripts:

| Script                     | Runs                                 | When                                        |
| -------------------------- | ------------------------------------ | ------------------------------------------- |
| `bun run drizzle:generate` | `drizzle-kit generate`               | After every schema change                   |
| `bun run drizzle:migrate`  | `drizzle-kit migrate`                | Apply pending migrations to the local DB    |
| `bun run drizzle:push`     | `drizzle-kit push`                   | Throwaway databases only (skips migrations) |
| `bun run drizzle:studio`   | `drizzle-kit studio --port=3443`     | Inspect data                                |
| `bun run drizzle:seed`     | `bun run src/drizzle/seeds/index.ts` | Seed the database                           |

Pass a migration name through: `bun run drizzle:generate --name add_tracks`.

- Always generate a migration for schema changes and read the SQL before applying it.
  Prefer `drizzle:migrate` over `drizzle:push` so the migration history stays the source
  of truth.
- Never edit an applied migration — add a new one.
- Seeds must be idempotent (`onConflictDoNothing()` keyed on slug) and must end the
  process (close the client) so the script exits.
