# Upscale (`tests/upscale.spec.ts`)

สคริปต์ Bun สำหรับอัปสเกลวิดีโอด้วย AI และเพิ่มเฟรมเรตให้ทุกไฟล์ในโฟลเดอร์ โดยใช้ [Video2X 6.x](https://github.com/k4yt3x/video2x) ร่วมกับ FFmpeg

รันจาก root ของ repo:

```bash
bun tests/upscale.spec.ts --dir /d/Workspace/media --scale 1080p --frame 60
bun tests/upscale.spec.ts --dir D:/Workspace/media --scale 2160p --frame 60 --content anime --dry-run
```

## ตัวเลือก

| Flag | ค่า | ความหมาย |
|---|---|---|
| `--dir` | path | โฟลเดอร์ที่เก็บวิดีโอต้นฉบับ (ไม่ค้นในโฟลเดอร์ย่อย) รับได้ทั้ง `D:/...` และ `/d/...` แบบ Git Bash |
| `--scale` | `720p` `1080p` `1440p` `2160p` (หรือ `2k` `4k`) | ความละเอียดเป้าหมาย นับจากด้านสั้นของภาพ จึงใช้กับวิดีโอแนวตั้งได้ด้วย |
| `--frame` | `30` `60` | เฟรมเรตเป้าหมาย |
| `--content` | `real` (ค่าเริ่มต้น) / `anime` | `real` ใช้โมเดล realesrgan-plus เหมาะกับคลิปจริง · `anime` ใช้ realesr-animevideov3 เหมาะกับการ์ตูน และเร็วกว่ามาก |
| `--out` | path | โฟลเดอร์ปลายทาง (ค่าเริ่มต้น `<dir>/upscaled`) |
| `--gpu` | ตัวเลข | ลำดับ GPU ของ Vulkan (ดูได้จาก `video2x -l`) ค่าเริ่มต้น `0` |
| `--video2x` | path | ตำแหน่ง `video2x.exe` ถ้าไม่ได้อยู่ใน PATH หรือโฟลเดอร์ติดตั้งปกติ |
| `--overwrite` | | ประมวลผลซ้ำแม้มีไฟล์ผลลัพธ์อยู่แล้ว |
| `--dry-run` | | แสดงแผนและคำสั่งที่จะรัน โดยไม่รันจริง |

ไฟล์ผลลัพธ์จะตั้งชื่อเป็น `<ชื่อเดิม>_1080p_60fps.mp4` ถ้ามีไฟล์ไหนล้มเหลว สคริปต์จะทำไฟล์ถัดไปต่อ และจบด้วย exit code `1`

## ขั้นตอนการทำงานต่อไฟล์

สคริปต์จะรันเฉพาะขั้นตอนที่จำเป็นสำหรับไฟล์นั้น

1. **อัปสเกล** ด้วย Video2X + Real-ESRGAN (2x/3x/4x) ทำเฉพาะเมื่อต้นฉบับเล็กกว่าเป้าหมาย
2. **เพิ่มเฟรม** ด้วย Video2X + RIFE (x2/x3) และเปิดการตรวจจับฉากตัด เพื่อไม่ให้เกิดภาพเบลอซ้อนตรงรอยต่อฉาก
3. **เข้ารหัสสุดท้าย** ด้วย FFmpeg
   - ย่อหรือขยายด้วย Lanczos ให้ได้ขนาดพอดีเป้าหมาย
   - ปรับ fps หากยังไม่ตรง
   - เข้ารหัสเป็น HEVC 10-bit ผ่าน NVENC (หากไม่มี NVENC จะใช้ libx265 แทน)
   - ดึงเสียงจากไฟล์ต้นฉบับมาใส่

เหตุผลที่อัปสเกลก่อนเพิ่มเฟรม: Real-ESRGAN เป็นขั้นตอนที่ช้าที่สุด ถ้าทำก่อน จะประมวลผลแค่เฟรมต้นฉบับ ไม่ใช่จำนวนเฟรมที่เพิ่มขึ้นเป็นสองเท่าแล้ว

ไฟล์ชั่วคราวระหว่างขั้นตอนจะเก็บไว้ที่ `<out>/.work/` และถูกลบเมื่อทำเสร็จ

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `tests/upscale.spec.ts` | Entry: อ่าน argument, เช็กเครื่องมือ, วนทีละไฟล์ และสั่งแต่ละขั้นตอน |
| `upscales/validator.zod.ts` | Zod schema ของ argument (`argsValidator`) |
| `upscales/constants.ts` | ค่าที่ปรับได้ทั้งหมด: โมเดล, คุณภาพ, threshold, นามสกุลไฟล์ |
| `upscales/source.ts` | หาไฟล์วิดีโอในโฟลเดอร์ และตั้งชื่อไฟล์ผลลัพธ์ |
| `upscales/ffprobe.ts` | อ่านขนาด, เฟรมเรต, การหมุน, เสียง และความยาวของวิดีโอ |
| `upscales/plan.ts` | ตัดสินว่าไฟล์นี้ต้องอัปสเกลกี่เท่า เพิ่มเฟรมกี่เท่า และต้องย่อ/ปรับ fps หรือไม่ (pure function) |
| `upscales/video2x.ts` | หา Video2X, สร้าง argument ของขั้นอัปสเกลและเพิ่มเฟรม, รันพร้อมรับมือกับการแครชตอนปิด |
| `upscales/ffmpeg.ts` | เลือก encoder, สร้าง filter และคำสั่ง FFmpeg ของขั้นเข้ารหัสสุดท้าย |
| `upscales/utils.ts` | แปลง path, จัดรูปแบบ log และรันคำสั่ง |

ใช้ `missingTools()` และ `errorMessage()` ร่วมกับ `tests/tracks/` และ log ผ่าน `logger()` จาก `@/libs/logger`

## ติดตั้ง Video2X (Windows)

```powershell
$tag = (Invoke-RestMethod https://api.github.com/repos/k4yt3x/video2x/releases/latest).tag_name
curl.exe -LO "https://github.com/k4yt3x/video2x/releases/download/$tag/video2x-windows-amd64.zip"
Expand-Archive .\video2x-windows-amd64.zip "$env:LOCALAPPDATA\Programs\video2x" -Force
```

สคริปต์จะหา `video2x.exe` จาก 3 ที่ตามลำดับนี้

1. `--video2x <path>`
2. `PATH`
3. `%LOCALAPPDATA%\Programs\video2x\video2x.exe`

หาก Video2X ปิดตัวทันทีที่เปิด ให้ติดตั้ง [VC++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe)

ถ้าไม่พบ Video2X สคริปต์ยังทำงานกับไฟล์ที่ไม่ต้องใช้ AI ได้ (เช่น ย่อขนาด หรือลด fps)

## ความเร็วโดยประมาณ (RTX 5080, Video2X 6.4.0)

| ขั้นตอน | ความเร็ว |
|---|---|
| `real` (realesrgan-plus x4) จาก 360p | ~3 fps |
| `anime` (animevideov3 x4) จาก 360p | ~44 fps |
| `anime` (animevideov3 x2) จาก 1080p | ~8 fps |
| RIFE ที่ 1440p | ~24 fps |
| RIFE ที่ 2160p (UHD mode) | ~11 fps |

ตัวอย่าง: คลิป 10 นาทีที่ 30fps มี 18,000 เฟรม ถ้าใช้โหมด `real` จาก 360p จะใช้เวลาราว 1.5–2 ชั่วโมงเฉพาะขั้นอัปสเกล ถ้าต้นฉบับเป็น 720p จะช้ากว่านั้นประมาณ 4 เท่า

## ปัญหาที่รู้แล้วของ Video2X 6.4.0

- **Video2X ปิดตัวผิดปกติหลังทำงานเสร็จ:** บน Windows มักแครชตอนปิดโปรแกรม (exit code 5 หรือ access violation) ทั้งที่เขียนไฟล์เสร็จครบแล้ว สคริปต์จะยอมรับผลนี้เฉพาะเมื่อ Video2X แสดงข้อความ `Video processed successfully` และ ffprobe ยืนยันว่าความยาวไฟล์ครบ ถ้าไม่ครบทั้งสองข้อ จะถือว่าไฟล์นั้นล้มเหลว
- **เฟรมท้ายคลิปหายไปเล็กน้อย:** หายประมาณ 2–5 เฟรมต่อขั้นตอน (ไม่ถึง 0.2 วินาที) ทำให้เสียงยาวกว่าภาพเล็กน้อยในช่วงท้ายคลิป

## หมายเหตุเรื่องคุณภาพ

- **อย่าขยายเกิน 4 เท่า** เช่น 360p → 2160p คือ 6 เท่า AI ทำได้สูงสุด 4 เท่า ส่วนที่เหลือเป็นการขยายภาพธรรมดา ช่วงที่ให้ผลดีที่สุดคือ 2–3 เท่า
- **โหมด `real` อัปสเกล 4 เท่าเสมอ** เพราะโมเดลมีแค่ 4x แล้วค่อยย่อลงให้ได้ขนาดพอดี คุณภาพดีที่สุดแต่ช้าที่สุด
- **ต้นฉบับ 29.97fps จะได้ผล 59.94fps** สคริปต์ไม่บังคับให้เป็น 60 พอดี เพราะการบังคับจะทำให้เกิดเฟรมซ้ำ
- **ต้นฉบับ 24/25fps** จะเพิ่มเฟรม x3 แล้วลดลงเหลือ 60 อาจเห็นการกระตุกเล็กน้อย
- **ปรับค่าต่างๆ ได้ที่ `tests/upscales/constants.ts`**: `FINAL_QUALITY` (คุณภาพไฟล์สุดท้าย), `SCENE_THRESHOLD` (ความไวในการจับฉากตัด), `RIFE_MODELS` (ลำดับโมเดล RIFE ที่จะลองใช้)
